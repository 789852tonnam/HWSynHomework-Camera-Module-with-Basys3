§00 · The Brief

What we were asked to build

In one screen.

Take live video from a tiny camera. Move every pixel through an FPGA. Show the result on a monitor. Add four filters the user can switch between with the slide switches on the board.

The four filter modes

The user picks one with two slide switches (SW[1:0]). Every pixel of every frame goes through the chosen filter.

SW · 00

RAW

Show what the camera sees, untouched.

SW · 01

INVERT

Photographic negative. Bitwise NOT.

SW · 10

COLOR ISOLATION

Keep one color channel, kill the rest. Channel from SW[3:2].

SW · 11

EDGE

Find the outlines (Sobel kernel). Threshold from SW[7:4].

The +5 extra credit

The base spec lets you cheat by shrinking the image to 320×240. Real 640×480, kept all the way through, is worth +5 points — and it is much harder because the on-chip RAM is not big enough. Both versions live in this repo.

§01 · Hardware

The pieces sitting on the desk

Three silicon things, glued together.

Board

Digilent Basys 3

Educational FPGA board. Xilinx XC7A35T-1CPG236C. 100 MHz crystal. 16 switches, 5 buttons, 16 LEDs, a 4-digit 7-seg, USB, VGA, two Pmod headers.

≈ 1.84 Mbit BRAM · 50 BRAM36 tiles

Camera

OV7670 Pmod

A $5 VGA-resolution CMOS sensor. 8-bit parallel data bus + sync (HREF, VSYNC) + I²C-like config bus (SCCB). Outputs RGB565 by default.

XCLK ← 24 MHz · PCLK → ~24 MHz · D[7:0] · HREF · VSYNC · SIOC · SIOD

Display

Any VGA monitor

Basys 3 has a built-in 12-bit VGA port — 4 bits per channel via a resistor ladder DAC. Plug in any old monitor that takes the blue connector.

640×480 @ 60 Hz · 25 MHz pixel clock

Two interesting notes:

  • PCLK → A16 The camera's pixel clock comes back into the FPGA on a normal I/O pin, not a dedicated clock pin. Vivado refuses by default; we override with CLOCK_DEDICATED_ROUTE FALSE. Works at 25 MHz on this small design.
  • SCCB needs pull-ups The config bus is open-drain, like I²C. Basys 3 Pmod has no external pull-ups, so we use the FPGA's internal ones (set_property PULLUP true).

§03 · The Memory Wall

Why we cannot just store the picture

A 640×480 picture
does not fit.

On-chip RAM (BRAM) is the FPGA's fast, dedicated picture-storage. The XC7A35T has 50 tiles, totaling about 1.84 megabits. A naive 640×480 RGB picture is 3.69 megabits. Two times too big.

So the entire 640 path is structured around one question: how do we throw away half the bits without it looking terrible?

Bits required to store one 640×480 frame · vertical line = chip limit

YCbCr 4:2:2 + aggressive bit-depth reduction (Y=3 bits, Cb=Cr=2 bits) is the winner: it fits, and human eyes — which evolved to resolve brightness much better than color — barely notice the chroma loss. This is the same trick JPEG, MPEG, HDMI 4:2:2, and DV use. We just push it further than usual.

The chroma quantization bins

Each chroma value is signed (it can be positive or negative — that's what "blue vs yellow" means). We bucket it into 4 bins at the thresholds shown below:

bin 0 :  diff <  -48      strong deficit
bin 1 :  -48 ≤ diff < 0   mild deficit  ← NEUTRAL pixel (R=G=B) lands here
bin 2 :   0  ≤ diff < 48  mild positive
bin 3 :  diff ≥ 48        strong positive

One of the most painful bring-up bugs: if bin-1 doesn't decode to "no offset," every neutral gray pixel comes out tinged green. Fixed by tuning the LUT so bin-1 = 0 offset.

How each mode works inside the FPGA

  • RAW Wire the BRAM read straight to the VGA port. No arithmetic.
  • INVERT One XOR with all-ones per channel. Two LUTs.
  • COLOR ISO Three muxes — pass one channel, force the other two to zero. SW[3:2] picks which.
  • EDGE The big one. Run a 3×3 Sobel kernel over the brightness channel, compute |Gx|+|Gy|, compare to the threshold from SW[7:4], output white-on-black.

§06 · Sobel kernel

How the edge filter actually works

A 3×3 magnifying glass

At every pixel, look at its 8 neighbors. Multiply each by a number (the kernel weights), add them up, take the absolute value. That's Gx for the horizontal direction and Gy for vertical. Sum them. If the result is bigger than the threshold, paint white. Else black.

The hardware trick: line buffers

To compute the kernel at row r, column c, the FPGA needs rows r-1, r, r+1 all available at the same time. But pixels arrive one at a time, in scan order. The fix: three line buffers — small RAMs each holding one full row. They rotate: as a new row arrives, the oldest gets overwritten. At any instant, three rows of luma are addressable.

Subtle bug avoided in the 640 path: the buffer being written this cycle returns the old value if you also read it. The fix is to forward pix_in directly into the bottom-right of the window, bypassing the RAM read.

§08 · Engineering

The cross-cutting techniques

Things that don't show up
in screenshots.

Clocks

MMCM × 2 outputs

One 100 MHz crystal becomes 25 MHz (VGA) + 24 MHz (camera XCLK). Through Vivado's MMCME2_BASE primitive. VCO at 1200 MHz.

Cross-domain

Dual-clock BRAM

The frame buffer is the entire CDC. Camera writes at 24 MHz, VGA reads at 25 MHz. The BRAM hardware handles the handshake.

Pulse CDC

Toggle synchronizer

VSYNC pulse needs to cross domains for the frame-rate LED. Toggle flop + 3-FF synchronizer + edge detect. ASYNC_REG attribute keeps the flops in one slice.

SCCB

Open-drain FSM

7-state machine sends 3-byte writes (ID, sub-addr, data). Bus is open-drain — drive low or float. 77 registers walked at start-up.

Debouncing

20-bit stable counter

Every switch and BTNC: two-flop sync + 2²⁰-cycle stability counter (~42 ms). Mechanical bounce filtered out.

Geometric

Flip + mirror, free

Camera mounting orientation makes the picture upside-down and mirrored. Fixed inside rd_addr: line_base counts down, mirror_x = 639 − h_count. No multiplier inferred.

Pipeline depth · the alignment dance

A pixel doesn't appear at the VGA pin the same cycle it's read. Every register in the path adds one cycle of delay. To make the picture line up, the active_video signal — which says "draw now" — has to be delayed by exactly the same amount.

   STAGE                              CYCLES   FILE
   ────────────────────────────────   ──────   ──────────────────────────
   rd_addr from h_count               0        vga_timing.v   (combinational!)
   frame_buffer BRAM read             1        frame_buffer.v
   filter_pipeline output reg         1        filter_pipeline.v
   ────────────────────────────────   ──────
   Total RAW / INV / ISO              2 cycles
   EDGE adds line_buffer3             +1
   ────────────────────────────────   ──────
   Total EDGE                         3 cycles → black border absorbs the 1-pixel diff

The earlier rebuild had 4 cycles. Result: every pixel was shifted 4 columns right of where it should be. Cured by stripping out two redundant register stages.

§10 · Limits

What's still imperfect

Honest about
the rough edges.

color

Recognizable, not accurate

2 bits of chroma per pair is a hard ceiling. Going higher would need either compression or another BRAM strategy.

edge mode

Shimmering on fine detail

Sub-pixel jitter from running Sobel on aggressively quantized luma. A 3-tap horizontal blur would fix it but needs another line buffer.

tearing

No double buffer

60 Hz read vs ~30 Hz write means a moving tear band. Acceptable for preview, but a true double buffer needs ~3 Mbits we don't have.

camera

AGC settle

Auto exposure is on; the camera adjusts itself for several seconds at power-up before the picture stabilizes.

Not a dedicated clock pin

Vivado refuses to route PCLK through the clock network by default. Requires set_property CLOCK_DEDICATED_ROUTE FALSE in the XDC. Works reliably at 24 MHz on this small design.

Internal pull-ups required

SCCB is open-drain. The Pmod connector has no external pull-up resistors, so both lines need set_property PULLUP true in the XDC to keep them high when not driven low.

§10 · Module Detail

Every RTL file, dissected

Fourteen files.
One picture.

The 640 path is split into small, single-responsibility modules. Each one does one job; they are wired together in top.v.

rtl/top.v

Top Wrapper

Routes clocks, resets, and switches. Instantiates every sub-module. SW[1:0]=filter mode, SW[3:2]=iso channel, SW[7:4]=Sobel threshold, SW[8]=OV7670 colorbar test, SW[9]=FPGA test pattern.

rtl/clk_wiz_main.v

MMCM Wrapper

100 MHz → 25 MHz (VGA pixel clock) + 24 MHz (camera XCLK). VCO runs at 1200 MHz; CLKOUT0 ÷48 = 25 MHz, CLKOUT1 ÷50 = 24 MHz. Outputs LOCKED signal to hold design in reset until clocks are stable.

rtl/cam_config.v

77-entry SCCB ROM

Sequentially walks a 77-register ROM at start-up. Sets COM7=0x04 (RGB output), COM15=0xD0 (RGB565 full swing), AWB, and gamma registers. Waits for done from sccb_master before advancing to the next entry.

rtl/sccb_master.v

7-state Open-drain FSM

States: S_IDLE→S_START→S_LOW→S_HIGH→S_STOP_A→S_STOP_B→S_STOP_C. Sends 27 bits (3 × 8-bit payload + DC bit per byte). Bus is open-drain: drive 0 or release to Z. HALF_PER_CYCLES=128 → ~49 kHz SCL.

rtl/cam_capture.v

RGB565 → YCbCr Capture

Pairs two incoming bytes (b1 + d_in) to reconstruct RGB565. Computes Y8=(77R+150G+29B)>>8. Quantizes Cb/Cr to 2-bit bins using thresholds −48/0/+48. Writes luma every pixel, chroma only on even columns (4:2:2).

rtl/frame_buffer.v

Split Dual-clock BRAM

luma_mem[307200]×3b + chroma_mem[153600]×4b. Write port clocked at cam_pclk 24 MHz; read port at clk_25. Chroma address = wr_addr[18:1] for 4:2:2 column sharing between odd and even pixels.

rtl/ycbcr_to_rgb444.v

Bayer Dither + LUT Decode

2×2 Bayer dither: (h_pos XOR v_pos) → dither bit appended to Y3 → Y4. Case-statement LUTs give r_off/b_off/g_off for each Cb2/Cr2 bin. Output clamped to 4-bit RGB444.

rtl/filter_pipeline.v

4-mode Filter Mux

2'b00=RAW (ycbcr_to_rgb444 direct), 2'b01=INVERT (~raw), 2'b10=COLOR ISO (zero non-selected channels), 2'b11=EDGE (line_buffer3 + filter_edge Sobel). All paths registered 2 cycles for alignment.

rtl/line_buffer3.v

3-row Circular Buffer

Three WIDTH×3b distributed RAMs rotating per row. bot_r is forwarded directly from pix_in to avoid write-before-read hazard on the current row. Produces a 3×3 window: rows (h−2, h−1, h) × columns (top, mid, bot).

rtl/filter_edge.v

Sobel L1 Edge Detector

Gx = right_col − left_col, Gy = bot_row − top_row. Magnitude = |Gx|+|Gy| (L1 norm, 7-bit). Outputs 12'hFFF if magnitude > threshold AND not on horizontal/vertical edge border, else 12'h000.

rtl/vga_timing.v

VESA 640×480@60 Hz

H_TOTAL=800, V_TOTAL=521. Read address is combinational; mirrors horizontally via 639−h_count. line_base counts DOWN for vertical flip. 3-cycle prefetch pipeline (PIPE=3) aligns BRAM data with active_video.

rtl/debouncer.v

20-bit Stable Counter

Two-FF synchronizer followed by a 2²⁰-cycle stability counter. Input must hold steady for ~42 ms at 25 MHz before the output updates. Suppresses all mechanical contact bounce.

rtl/cdc_pulse_sync.v

Toggle-flop CDC

Toggle flop in source domain → 3-FF synchronizer in destination domain → edge detect to recreate pulse. ASYNC_REG attribute keeps synchronizer flops in the same slice to minimize metastability window.

§12 · Challenges

What went wrong, and why

Eight hard things.

The problems that required the most iteration, debugging time, or architectural rethinking.

01 · Camera bring-up

OV7670 power-up timing

Reset hold time, post-reset wait, and per-register SCCB gap all need careful tuning. The sensor silently ignores writes or boots into the wrong output format if timing is even slightly off.

02 · Memory

The BRAM wall

640×480 RGB565 = 4.9 Mbits; the chip has 1.84 Mbits. We had to commit to YCbCr 4:2:2 with Y3+Cb2+Cr2 = 5 bpp (1.54 Mbits) before any feature work could begin.

03 · Clocks

Clock Domain Crossing

Two asynchronous domains (24 MHz camera, 25 MHz VGA) plus the PCLK input. CDC was confined to the dual-port BRAM boundary and a dedicated cdc_pulse_sync module to avoid metastability.

04 · Color bug

Green tint

Chroma decoder bin-1 had a non-zero offset, so every neutral gray appeared green. Fixed by making the LUT antisymmetric: bin-1 = 0 offset in all four tables (r_off, b_off, gOffCr, gOffCb).

05 · Pipeline

Pixel alignment (right-shift bug)

Pipeline depth was 4 cycles, so the picture appeared shifted 4 columns right. Fixed by removing redundant register stages to reach the correct 2-cycle depth.

06 · Dual codebase

320 vs 640 code split

Both resolution paths live in the same repo with different storage schemes. Keeping both in sync during architectural refactors was non-trivial.

07 · Quantization

Sobel on 3-bit luma

Coarse quantization makes threshold tuning critical. Adding a Bayer dither bit (Y3→Y4 before filtering) significantly recovered fine-detail discrimination.

08 · Routing

PCLK routing

Pin A16 is not a dedicated clock pin. Vivado rejects the placement by default. Required CLOCK_DEDICATED_ROUTE FALSE as an XDC override. It works at 24 MHz on this small design, but would not scale to higher frequencies.

§14 · Glossary

Acronyms decoded

If a word looked alien.

FPGA
Field-Programmable Gate Array. A chip whose internal wiring you reconfigure with code. Different from a CPU — there's no instruction stream; the code becomes actual hardware.
Verilog
The hardware-description language used to write that "code." Looks vaguely like C; behaves like a circuit diagram.
BRAM
Block RAM. Dedicated on-chip memory blocks. Fast, fixed sizes, limited quantity (50 tiles on this board).
Pmod
A 12-pin header standard on Digilent boards for plugging in peripheral modules like cameras.
VGA
The blue-connector display standard from the 90s. Three analog channels (R/G/B) plus two sync pulses (HSYNC/VSYNC). Still ubiquitous.
RGB565
16-bit color: 5 bits red, 6 bits green, 5 bits blue. The OV7670's default output format.
RGB444
12-bit color: 4 bits per channel. What the Basys 3's resistor-ladder VGA DAC supports.
YCbCr
A color encoding that separates luminance (Y) from chrominance (Cb, Cr). Lets you compress color much more than brightness — which matches how human vision works.
4:2:2
Chroma subsampling ratio: full-resolution Y, half-horizontal-resolution Cb and Cr. Same trick as DV, MPEG, HDMI 4:2:2.
SCCB
Serial Camera Control Bus. OmniVision's nearly-but-not-quite I²C, used to configure the OV7670.
HREF / VSYNC
Horizontal Reference / Vertical Sync. The camera's sync pulses telling you "pixels in this row are valid" and "new frame starts now."
PCLK
Pixel Clock — the camera tells the FPGA "here's a new pixel byte" by toggling this line.
MMCM
Mixed-Mode Clock Manager. The Xilinx primitive that multiplies/divides clocks. We use it to make 25 MHz and 24 MHz from 100 MHz.
CDC
Clock Domain Crossing. Moving signals safely between two unrelated clocks. Done wrong, you get random metastability bugs.
Sobel
A 3×3 image kernel for edge detection. Computes brightness gradients in X and Y, sums their magnitudes.
Bayer dither
A cheap pattern (here, 2×2 checkerboard) for reducing visible banding when you truncate bits. The eye averages it out.
Quantization
Reducing precision. 8-bit → 3-bit means 256 levels become 8 levels. Information is lost; the trick is to lose what doesn't matter.
L1 magnitude
|Gx| + |Gy|. The cheap version of "vector length." Real length is √(Gx² + Gy²) but that needs a multiplier and square root we don't have time for at 25 MHz per pixel.
